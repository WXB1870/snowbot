# Snowbot 部署与运行

[项目首页](../README.md) · [首次准备](#首次准备与构建) · [日常启动](#日常启动) · [仿真](#仿真与浏览器操作台)

本文命令均在 Snowbot 仓库根目录执行。

`tools.deployment.deploy` 按 `dependencies.repos` 获取配套 Bindu，构建底层和两仓上层软件；构建与设备启动分开。

## 支持条件

- Ubuntu 24.04／x86_64、ROS 2 Jazzy、系统 Python 3.12、colcon、rosdep；实时 Linux 与调度权限已配置。
- `/opt/openrobots` 中的 Pinocchio 4.1.0 C++ 库及 CMake 配置；底层与上层数值 venv 分别加载依赖。
- PDO 布局为双臂各8轴、头部和腰部各2轴；会话控制双臂各7轴和腰部，夹爪独立控制。消息须配对生成、构建和安装；接入检查发布者唯一性、节点／GID、类型名及 QoS。
- EtherCAT 网卡、原始套接字权限、急停、零位／限位、工具和夹爪标定已确认；PICO 远程访问需网络与 TLS 证书。

已安装 ROS 的机器可补齐工具：

```bash
sudo apt-get install git patch build-essential cmake python3-dev python3-venv \
  python3-colcon-common-extensions python3-rosdep libeigen3-dev libyaml-cpp-dev libboost-all-dev
# 首次使用 rosdep 且尚未初始化时执行 sudo rosdep init
rosdep update
```

`prepare` 安装 ROS 及锁定的 Python 依赖；Pinocchio C++ 环境需预先安装。

## 首次准备与构建

```bash
git clone https://github.com/WXB1870/snowbot.git
cd snowbot
git checkout '<选定的Snowbot提交或发布标签>'
python3 -m tools.deployment.deploy prepare
```

已有 Bindu 可传 `--bindu-source /绝对路径/bindu`，须匹配依赖锁且 `src/`、`tools/` 干净。阻抗分支的新 workspace 首次准备加 `--with-impedance`；运行模式另由现场配置选择。

Bindu 位于 `artifacts/dependencies/bindu/`，默认产物位于 `artifacts/robot/`：

| 内容 | 相对产物目录的路径 |
|---|---|
| 底层源码与来源清单 | `vendor/src/`、`vendor/position_release.json` |
| 底层安装／缓存／日志 | `vendor/install/`、`vendor-build/`、`vendor-log/` |
| 上层安装与数值环境 | `upper/install/`、`upper/venv/` |
| 现场配方与 servo 参数 | `upper/site.json`、`vendor-position.yaml` |
| 版本与配置回执 | `deployment-manifest.json` |

自定义 `--workspace` 后，准备、构建和启动均使用该目录。底层修改维护在准备器、补丁及公共头中；生成源码被手改时保留原目录，另选 workspace。

## 首次现场配置

`upper/site.json` 首次生成时默认 `command_enabled=false`、监听 `127.0.0.1`。按现场核对：

1. **模型与工具**：选择 `robot_config`、profile 和工具；实机／仿真共用宽限位 `snowbot_control.urdf`，profile 与 vendor 限位须对齐。姿态参考余量为0.027453292519943294 rad；单机覆盖放在部署目录。
2. **PICO 与夹爪**：核对准备位、握点、工具几何和底盘端点。`teleop.json`／`grippers.json` 按 `modes.real|simulation` 选择准备姿态、握持确认和夹爪参数；握持确认分别为 `operator|calibrated`。夹爪模板角度：左开−0.8／闭0.26，右开0.8／闭−0.26／虚握−0.24 rad，须现场标定。
3. **浏览器**：site 中填写监听地址、`cert_file`、`key_file`；PICO HTTPS 默认8012，电脑页面8013，私钥留在本地。
4. **动态限制**：核对 profile 与 `vendor-position.yaml`。默认 v/a/jerk：双臂1.0/4.5/162，腰部0.6/3.6/259.2，servo公共上限1.0/4.5/259.2（单位依次为 rad/s、rad/s²、rad/s³）。腰部减速比从 `0x200E:02` 读取，读取失败暂用101，错误响应拒绝初始化；现场须核实。

### VR 常驻等待页（直连与远程）

希望先打开眼镜、再启动 VR 程序时，在眼镜访问的主机上独立运行 Nginx。眼镜始终打开 `https://入口主机:8012/`。VR 服务未启动时，等待页每 3 秒重试；启动后自动进入原来的 VR 页面。进入页面后按原流程开始遥操作。

| 使用方式 | 入口主机 | [Nginx 模板](../tools/deployment/nginx/snowbot-vr.conf) 中的上游地址 |
|---|---|---|
| 局域网直连机器人 | 机器人 | `127.0.0.1:8014`。在部署的 `upper/site.json` 中将 `arguments.host` 设为 `127.0.0.1`、`arguments.port` 设为 `8014`，保留 VR 服务的 HTTPS 证书配置 |
| 经本地电脑远程访问 | 本地电脑 | 把 `upstream` 中的 `server` 改为机器人穿透 IP 和 HTTPS 映射端口。机器人也启用等待页时，穿透目标指向机器人 Nginx 的 `8012` |

每台入口主机各使用一份模板，将证书和私钥路径改为该机已有路径。眼镜须信任证书并用证书覆盖的域名或 IP 访问。安装到 Ubuntu 的 `/etc/nginx/conf.d/snowbot-vr.conf` 后，运行 `sudo nginx -t` 检查，再由现场人员启用 Nginx 开机启动并加载该配置。原先用 `socat` 占用本地 `8012` 的，需先释放该端口。直连继续选择本地 VR 参数，远程继续选择远程参数。等待页仅依赖入口主机开机和 Nginx 运行。

默认位置判据：

| 判据 | 默认值 | 维护来源 |
|---|---|---|
| 目标流参考／实测跟踪偏差 | 0.5 rad | `pause_hold.patch` |
| 双臂回零触发／退出容差 | 0.5°（约0.008727 rad） | `drive_maintenance.patch` |
| 双臂回零超时接纳残差 | 0.01 rad | `kRetzeroTimeoutAcceptError` |
| 腰部停止到位容差 | 1° | 底层腰部控制逻辑 |

### 共享运行参数与servo启动参数

`site.json` 的 `arguments.parameters_config` 默认指向 [runtime_parameters.json](../src/snowbot_bringup/config/robots/snowbot/runtime_parameters.json)，现场 JSON 只写覆盖项。PICO、求解、执行和预检共用这份启动配置；独立离线入口通过双臂工具文件引用同目录的共享默认时序。

参数及默认值直接查上述文件，时间通常为秒，`display` 为毫秒。单次求解须短于worker往返预算，制动预留须短于目标有效期；原始源时间与期限随目标传递。夹爪行程／增益在 `grippers.json`，右轴切换阈值在工具配置。

准备目标默认250 ms、发送周期40 ms，须满足 `prepare_command_period_s + target_stream_brake_lead_s < prepare_command_ttl_s`。续租周期短于租约期限（臂2 s，夹爪见 `lease_ttl_s`）。停止等待为 profile 的 `stop_timeout` 加运行参数的 `stop_wait_margin_s`，重发不延长原期限；profile 同时维护 `control_period`、`max_tick_gap` 和停止容差。

旧 site 的 `arguments.target_stream_brake_lead_s` 迁至共享参数的 `execution` 分组；旧值不一致时启动会提示。ROS反馈40 ms、PDO年龄20 ms在底层契约中维护；旧轨迹前视120 ms独立于目标流制动预留。

servo 从部署目录 `vendor-position.yaml` 读取速度估计和接管门限，字段见 [target_stream.yaml](../tools/deployment/snowbot_vendor/position_session/target_stream.yaml)。JSON 修改后重启第四终端，servo YAML 修改后重启对应进程；构建保留现场文件。

## 日常启动

正式运行固定使用`session_v3`。沿用`bash tools/run_robot.sh base`及`bash tools/run_robot.sh vr`，不再选择协议。迁移旧配置须删除`arguments.position_protocol`及servo YAML的`position_reference_mode`；直接ROS参数中的同名字段也会报错。`reference_mode=2`和目标配方version 2/3/4/5保留各自语义。旧Follower的`position_max_velocity/position_max_acceleration`须显式迁移到`trajectory_max_velocity/trajectory_max_acceleration`，`bindu_guard`须删除，旧键均会拒绝加载。当前main仅支持position，阻抗分支及118现场不在本次本机修改范围。


四个终端从同一 Snowbot 目录按 1→2→3→4 启动，保持相同 ROS 域与 RMW。前三个终端使用未激活 Conda／venv 的 Bash 环境。**servo 启动和退出可能回零／回位，启动前清空运动范围并确认急停可用；Ctrl+C 会进入退出流程。** 确认每层就绪后继续，已运行节点无需重复启动。

终端 1：servo。

```bash
sudo /bin/bash -c '
source "$1/tools/deployment/snowbot_vendor/env_118.sh" "$1/artifacts/robot/vendor" &&
exec ros2 run snowbot_servo_control servo_node --ros-args --params-file "$1/artifacts/robot/vendor-position.yaml"
' snowbot "$PWD"
```

终端 2：中层。

```bash
source tools/deployment/snowbot_vendor/env_118.sh "$PWD/artifacts/robot/vendor" &&
ros2 run snowbot_dual_arm_control dual_arm_control_node
```

终端 3：topic 上层。

```bash
source tools/deployment/snowbot_vendor/env_118.sh "$PWD/artifacts/robot/vendor" &&
ros2 launch robot_control robot_control.launch.py control_source:=topic
```

终端 4：Bindu、VR 与浏览器。

```bash
python3 -m tools.deployment.deploy start --enable-commands
```

正常启动直接初始化实际组件；完整依赖、QP 和接口巡检通过 `--check`／`--check --check-robot` 显式执行。启动保留互斥和执行租约，ROS 拓扑按100 ms刷新，反馈时效与停止确认仍持续检查。松开握键与扳机，等待 `SNOWBOT_STARTUP_HOLD_READY` 并确认保持正常后操作。自定义 workspace 时，将前三个终端的底层安装与参数路径替换为对应目录。

## PICO操作

| 操作 | 位置配方流程 |
|---|---|
| 左右 Squeeze | 普通模式逐侧接合，松开保持，重接建立新基准；耦合模式共同接合，松任一侧暂停工具 |
| B | 停稳松握后切换普通／耦合模式；跟随中先停止，再次按键切换；锁定时按状态提示恢复 |
| A | 停稳松握后长按并保持，返回侧铲准备位；松开停止 |
| 左右 Trigger | 停稳松握后分别控制对应夹爪：按住打开，有效释放闭合 |
| X | 默认位置配方持续释放右手绕杆轴转动，X 无需切换握持；旧配方沿用其虚握／回锁流程 |
| Y | 停止当前操作；恢复后重新接合 |

默认 `grasp_reference_source=measured_axial`：工具跟踪完整六维位姿，右手保持握点位置与轴向并允许绕轴转动，重接保留首次实测握点／轴向。该配方要求右夹持可转且不滑、左侧可承担轴向扭矩。模型参数见 [Bindu QP 说明](https://github.com/WXB1870/bindu/blob/main/src/capabilities/bindu_bimanual_qp/README.md#双臂qp参数与abi)。

普通双臂从当前实测末端接合，腰部与未接合臂保持。耦合模式检查工具几何与握持关系。首次使用按无工具、低幅运动、工具握持的顺序检查实际到位、停稳和夹持状态。

### 三元动作真机回放

统一入口 `tools/run_robot.sh`。两个终端先进入 `/home/cc/deployments/current`，终端1启动底层：

```bash
bash tools/run_robot.sh base
```

底层包含servo、中层和topic上层；main 的统一入口使用位置模式（`execution_mode:=position`）。模式在底层启动时选定，VR和回放读取实际模式，不重复传参。显示`SNOWBOT_BASE_STARTED`表示三层初始化完成；反馈异常仍会单独告警。终端2二选一：

```bash
bash tools/run_robot.sh vr
```

```bash
bash tools/run_robot.sh replay
```

`vr`启动执行器、PICO、浏览器和录包；`replay`启动执行器、空手Prepare到前推起始位、两次Enter开闭爪及分阶段菜单，已装好雪铲可用`bash tools/run_robot.sh menu`直接进入菜单。预设轨迹按各轴动态限值预先规划时长并保存，回放倍率固定使用1.0，不再统一乘1/3。退出上层释放控制权并等待停止确认，底层继续运行；底层终端最后退出。旧`run_primitives.sh`保留命令转发。

只按既有就绪状态等待，不增加夹爪／微小角度门槛。底层与回放执行器的完整进程输出异步按层保存到`artifacts/robot/startup-logs/`，启动时显示`LOGS`路径；终端只显示启动／退出、故障和WKC摘要，正常WKC每10秒一次，数值变化立即显示，重复告警每10秒汇总。servo启停可能回零／回位；Ctrl+C不是急停。

使用维护入口 `python3 -m snowbot_bringup.runtime.snowbot_primitive_replay`，或动作包中从同一维护源导出的 `replay.py`。默认只预览，打印过渡路线、总时长、起终关节姿态和校准参数。标准库随 snowbot_bringup 安装在 config/robots/snowbot/primitive-library；动作包从同一维护源导出。操作者使用已更新宽限位配置及 vendor 版本启动既有执行器。

首次进入准备位时先空手执行：

```bash
python3 replay.py --library manifest.json --action Prepare --execute --output prepare-001.jsonl
```

`Prepare` 不依赖 VR。执行时先保持当前夹爪状态，读取已停稳的全部实测关节，以动作库 `preparation.minimum_duration_s`（2秒）为下限，按实际距离和既有profile动态限值的80%计算平滑五次曲线耗时；先验证完整本体 CAD 路径，再获取16轴租约。不再使用30秒下限或90秒慢放；VR共用的 `teleop.json.prepare_duration` 保持原值，其他起点按实测计算。沿用 `measured_joint_limit_tolerance_rad`（实机2°）接纳实测小越界；数值边界偏差使用合法边界参考，较大偏差复用已确认的保持参考向内恢复，并检查实测点到参考点的完整本体路径。原始实测保留，所有下发目标仍在原限位内；超容差、碰撞或检查期间姿态变化则拒绝。准备运动期间头部和夹爪保持实测上下文，参考余量仍为0.027453292519943294 rad。到位并确认停止后，先等待操作者按 Enter 打开双爪；装夹雪铲后再次按 Enter 关闭双爪；实测闭合后结束准备，再选择三个动作。`Prepare` 的默认预览不操作夹爪，实际路径检查在 `--execute` 取得新鲜反馈后完成；Ctrl+C 仍走原租约释放与实测停止确认。

```bash
python3 replay.py --library manifest.json --action SideScoop --speed 1 --execute --tool-id g099-curved --output replay-side-001.jsonl
```

菜单中1前推独立执行，Enter拉回；2侧铲及抬铲完成后可选3翻倒或Enter返回；3只允许在2完成后执行，完成后Enter走独立倒空回程返回侧铲起姿，不自动再侧铲。各阶段保留停稳等待和q退出。程序根据新鲜实测匹配已验证的起终节点，连接到所选动作起姿；`Home` 只返回侧铲准备位。SideScoop 只执行侧前铲入，到承雪节点停下；Flip 从该节点继续翻倒。`--speed` 范围为 `(0,1]`；`--waist-lead` 按真实秒指定腰部命令相对手臂的提前量，默认使用动作包校准值，减速时该提前量不随速度缩放。姿态参考余量保留为0.027453292519943294 rad，命令目标和当前工具配置均须匹配。

回放起点匹配默认2°（`--start-tolerance`，单位rad）；到位位置容差取2°与现有配置的较宽值：Prepare当前0.035 rad（约2.005°），其余动作当前2°。停稳速度门限取运行参数与profile速度容差的较宽值，当前0.01 rad/s；持续窗口复用运行参数，当前0.1秒，接管与末点等待预算当前6秒。客户端允许的调度迟到和ROS／单调时钟偏差沿用命令有效期250 ms，不恢复旧40／20 ms门限。状态接收年龄上限200 ms、测量时间戳年龄上限300 ms；接管前须有持续更新的测量时间戳，超时不取租约。上述客户端判定不改变底层反馈、限位及停止保护。

离线预览默认从侧铲准备位开始，可用 `--from-node Push:end` 或 `--from-node Dump:end` 查看其他衔接路线。真实执行始终以实测匹配节点，不采用这个预览参数。

默认读取已安装的 `config/robots/snowbot/robot_snowbot_real.json`，现场覆盖配置可用 `--robot-config` 显式选择；执行器 profile 指纹必须一致。程序复用16轴联合租约和 `session_v3` 目标流，核对新鲜实测起姿、PDO进度、跟随误差和时钟；结束需要末点已发送、实测到位与释放后的停止确认。切换走双轴释放约束下验证的持铲路径，命令行衔接默认保留3秒停稳，分阶段菜单的衔接不额外停顿；路径保留左右允许的绕轴旋转。未知持铲起姿拒绝执行。VR 长按 A 使用同一张路径图返回侧铲准备位，松开仍停止；已明确空手、双爪已打开或 unheld_test 的普通双臂模式可走原本体避碰准备流程，并按慢腰预算延长时间。程序不启动驱动，不操作底盘或头部；仅Prepare按上述两次Enter确认操作夹爪。原生 Isaac 小窗用于仿真查看，真实回放由操作者显式执行上述命令。

当前预设库允许两腰参与，Prepare进入动作库`preparation.goal_node`指定的腰臂起姿，随后沿已保存曲线运动；VR准备配置不变。使用操作者提供的0.1秒等效纯延迟假设检查腰臂配合，未生成新的分轴辨识参数。前推名义刀口高度约1厘米，铲路保留并重新安排各段时长；优先各关节速度和平顺性，速度规划峰值约留15%余量，不强求每段2倍。Prepare仍按距离与动态限值计时。进入侧铲采用低位直达路径，倒空回程保留必要向外避让；节点q/v/a连续，菜单仍停稳等待。拉回和侧铲内部各保留5毫米、3毫米离地余量，以减小加速后的贴地压力，起终姿态不变。名义曲线和延迟预测均做握持／碰撞检查，完整仿真录像使用延迟预测作为腰部响应输入；实体阻抗、负载及±2厘米效果仍需现场验收。固定腰版保留在Git提交eab4164及本机实验目录。

预设动作保存曲线、动态、握持和碰撞检查后接受的完整50Hz q/qd/qdd及原多项式。回放一次提交定时曲线，之后只续250ms源TTL心跳；底层按原时间采样，不逐点重拟合。持铲曲线使用轨迹版本4和原参考余量，空手Prepare使用版本5允许从硬限位边界向内进入；需配套源码构建，当前未部署。执行日志同时保存完整参考与收到的实测关节诊断。

阻抗分支中的 Prepare、Home、三个原子动作及动作间转接共用名义参考：双臂由已冻结的118关节阻抗后端执行，腰部仍为位置控制。VR普通目标流在 `execution_mode=impedance` 时将双臂14轴和两腰分别计算曲线时长，避免手臂落后拖慢腰部；两组保持同一生效时间、命令身份与有效期，各自保留动态限制，PAUSE仍按16轴统一制动。分组会改变腰臂的相对运动进度，持铲世界轨迹及实体效果须另行验证。统一部署入口首次使用 `python3 -m tools.deployment.deploy prepare --with-impedance` 编入后端，后续 `build` 保留该选择；编入后端不自动切换运行模式。现场的上层与servo须已配对选择 execution_mode=impedance，并满足既有标定和传感器新鲜度条件。使用该分支安装的维护入口时显式选择模式，例如：

```bash
python3 -m snowbot_bringup.runtime.snowbot_primitive_replay --library /动作库/manifest.json --action Prepare --execution-mode impedance --execute --output prepare-impedance-001.jsonl
```

装夹后将 action 换为 Push、SideScoop 或 Flip，并增加 --tool-id g099-curved。实际 PDO 模式必须与请求一致；阻抗跟随预算读取现有 impedance_reference_limits（当前手臂0.25 rad、腰部0.15 rad），--follow-tolerance 可进一步收紧。回放沿用已验证的持铲路径和允许的两轴转动，不恢复已删除的客户端重复几何检查。刚度、阻尼沿用冻结配置；配置模板默认为位置模式，统一入口`run_robot.sh base`默认选择阻抗模式。阻抗动作从认证的PAUSE名义保持点衔接；完成条件为采样名义参考到位且实体实测停稳，结果分别记录 nominal_arrival_confirmed 与 measured_arrival_confirmed，并保留实测末点偏差。持续柔顺偏移仍受现有跟随预算与握持关系保护，不用于重设名义目标。

装夹并处于已验证节点后，可用编号菜单连续选择动作：

```bash
python3 -m snowbot_bringup.runtime.snowbot_primitive_replay \
  --library /动作库/manifest.json --interactive --execute \
  --execution-mode impedance --tool-id g099-curved --output-dir /动作日志目录
```

输入 `1`＋Enter前推，再按空Enter拉回，之后可选`1`或`2`；前推后不能直接选`3`。`2`只执行侧前铲，结束后只允许`3`翻倒或空Enter回到侧前铲初始位；翻倒后一次空Enter连续退回侧前铲初始位。切换沿用已验证转场，段间不再固定等待3秒；任意阶段`q`退出。每次动作和回退独立保存JSONL日志，执行异常退出菜单。

## 日常修改与更新

```bash
git pull --ff-only origin '<选定分支>'
python3 -m tools.deployment.deploy build
```

修改先留版，`build` 按依赖锁增量构建并保留现场配置；`--bindu-source` 指定的仓库只校验。系统、ROS、Python ABI、数值依赖或部署根目录变化时，另选 workspace 执行 `prepare`；新增系统依赖也需 `prepare`。

升级时按新模板核对 site 和 servo 参数；旧单仓迁移在新目录完成后再切入口。构建前须退出活动控制进程。

以下命令从仓库根目录构建仿真上层与底层消息：

```bash
s="$PWD"
b=$(python -c 'from tools.deployment.deploy import locked_bindu; print(locked_bindu(None, acquire=True))')
w="$s/artifacts/simulation"
source /opt/ros/jazzy/setup.bash

  --base-paths "$s/src" "$b/src" "$s/vendor/snowbot/original/ctl_msgs" \

  --cmake-args -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF \
  -DPython3_EXECUTABLE="$(command -v python)" -DPYTHON_EXECUTABLE="$(command -v python)"
```
